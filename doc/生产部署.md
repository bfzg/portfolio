# 生产部署文档

本文档用于把个人作品集网站部署到二级域名 **`my.etedrop.com`**，部署在**已运行 `etedrop.com` 的同一台服务器**上（新增子域名站点）。

当前项目使用本地 JSON 文件存储内容和本地上传目录，因此推荐用 VPS 部署。不要直接部署到无持久磁盘的平台，否则 `src/data/portfolio.*.json` 和 `public/uploads/` 可能丢失。

## 1. 部署目标

建议生产结构：

```text
my.etedrop.com  ->  Nginx（与 etedrop.com 同机）  ->  Next.js app:40323  ->  JSON src/data/portfolio.*.json
```

最低服务器配置：

```text
Ubuntu 22.04 / 24.04
1 核 CPU
512MB-1GB RAM
10GB 磁盘
```

> 本项目无数据库、无外部依赖，资源占用极低，512MB 内存即可运行。部署在 etedrop.com 同机时，复用其已有的 Nginx / Certbot / Node / PM2，无需重新安装基础环境。

## 2. 域名解析（新增子域名）

`my.etedrop.com` 是 `etedrop.com` 的二级域名，DNS 管理与主域名在同一个服务商账户。在服务商后台新增一条记录即可：

```text
类型    主机名(前缀)   值
A       my             服务器公网 IP（与 etedrop.com 指向同一台）
```

> 因为 `my` 是子域名，主机名只填 `my`；解析生效后它与 `etedrop.com` 解析到同一 IP，由本机 Nginx 按访问域名分流到不同站点。本部署不使用 `www.my.etedrop.com`。

若 `etedrop.com` 走 Cloudflare，子域名 `my` 默认也会走 Cloudflare 代理。申请证书期间建议先把 `my` 设为 **DNS only（灰云）**，证书签发成功后再按需切回 **Proxied**（SSL/TLS 模式用 Full 或 Full strict）。

验证解析生效：

```bash
dig +short my.etedrop.com
# 返回服务器公网 IP 即正常
```

## 3. 前提确认（服务器已具备）

部署前确认本机已具备运行环境（etedrop.com 已配置好的，正常都已就绪）：

```bash
# Nginx 已安装且 etedrop.com 站点正常
sudo nginx -t
systemctl status nginx --no-pager | head -5

# Node / PM2 已安装
node -v
pm2 -v

# Certbot 已安装、证书目录存在
certbot --version
ls /etc/letsencrypt/live/

# 40323 端口未被占用
sudo lsof -i:40323 || echo "40323 空闲，可用"
```

如果以上任一项缺失（例如这是台全新子机），先补齐：

```bash
apt update && apt upgrade -y
apt install -y git curl nginx certbot python3-certbot-nginx apache2-utils
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm install -g pm2
```

> 若服务器上已装过 Node / PM2 / Nginx（etedrop.com 部署时已装），直接跳过安装即可。

## 4. 拉取项目

建议放在 `/var/www/portfolio`（与 etedrop.com 的站点目录并列，互不干扰）：

```bash
mkdir -p /var/www
cd /var/www
git clone 你的仓库地址 portfolio
cd portfolio
npm install
```

如果不是用 git，也可以把项目上传到 `/var/www/portfolio`。若项目已存在，只更新代码：

```bash
cd /var/www/portfolio
git pull
npm install
```

## 5. 配置环境变量（可选）

本项目不需要必填的环境变量。如果需要自定义端口或站点信息，可创建 `.env.local`：

```bash
nano /var/www/portfolio/.env.local
```

可选配置：

```env
# 应用端口（默认 3000，本机用 40323 避免与 etedrop.com 既有服务冲突）
PORT=40323

# 站点元信息（影响 SEO 和浏览器标签页标题）
NEXT_PUBLIC_SITE_URL=https://my.etedrop.com
NEXT_PUBLIC_SITE_NAME=Zhou Shuo Portfolio

# 百度统计站点 ID（可选）
NEXT_PUBLIC_BAIDU_ANALYTICS_ID=your-baidu-analytics-id
```

注意：

- `NEXT_PUBLIC_SITE_URL` 建议配置为线上域名，方便分享和 SEO。
- `NEXT_PUBLIC_BAIDU_ANALYTICS_ID` 只填写 `hm.js?` 后面的 ID，不要填写完整脚本标签。
- 本项目无数据库、无支付、无管理员认证，不需要配置敏感凭证。
- 后台 `/admin` 的访问保护依赖第 9 章的 Nginx Basic Auth，而非环境变量。

## 6. 构建和启动

执行生产构建：

```bash
cd /var/www/portfolio
npm run build
```

用 PM2 启动（同一台机器的 PM2 可能已管理 etedrop.com 相关进程，这里用独立进程名 `portfolio` 避免冲突）：

```bash
PORT=40323 pm2 start npm --name portfolio -- start
pm2 save
pm2 startup
```

查看状态：

```bash
pm2 status
pm2 logs portfolio
```

生产环境建议监听 `40323` 端口，避免和服务器上的其他服务冲突（例如 fast_send_server 用 40321、yeezy 用 40322）。Nginx 只需要反向代理到 `127.0.0.1:40323`。与 `etedrop.com` 的站点完全隔离，互不影响。

## 7. 配置 Nginx（新增子域名站点）

`etedrop.com` 的 Nginx 配置已存在，本步只**新增** `my.etedrop.com` 的站点，不改动主域名配置。

> 重要：如果 `etedrop.com` 的配置已经在 `http {}` 块中定义过 `map $http_upgrade $connection_upgrade`，本配置的 `http` 块里**不要再重复定义**，否则 `nginx -t` 会报重复。本配置默认假设该 `map` 已存在，如需补充见第 8 章末尾说明。

首次部署时，`/etc/letsencrypt/live/my.etedrop.com/` 证书还不存在，不能直接启用含 `listen 443 ssl` 的完整配置。先写入只用于 ACME 校验的 HTTP 配置，签好证书后再换成完整 HTTPS 配置。

创建站点配置：

```bash
nano /etc/nginx/sites-available/portfolio
```

首次部署先写入：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name my.etedrop.com;

    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    location / {
        return 301 https://my.etedrop.com$request_uri;
    }
}
```

启用配置（文件名 `portfolio` 与 etedrop 站点区分开）：

```bash
ln -sf /etc/nginx/sites-available/portfolio /etc/nginx/sites-enabled/portfolio
nginx -t
systemctl reload nginx
```

## 8. 配置 HTTPS

确认 DNS 已经解析到服务器后，单独为子域名申请证书：

```bash
certbot certonly --webroot -w /var/www/html -d my.etedrop.com
```

说明：

- `my.etedrop.com` 的证书是**独立于 `etedrop.com` 主域名证书**的，两者各自续期，互不干扰。
- 如果服务器上已有 `*.etedrop.com` **通配符证书**且覆盖 `my.etedrop.com`，可直接复用，无需单独申请——把完整配置里的证书路径改成通配符证书路径即可。
- 若 `etedrop.com` 走 Cloudflare 代理，申请期间把子域名 `my` 临时切到 DNS only（灰云），签完再切回。

签完证书后，确认文件存在：

```bash
ls -la /etc/letsencrypt/live/my.etedrop.com/fullchain.pem
ls -la /etc/letsencrypt/live/my.etedrop.com/privkey.pem
```

如果服务器上已有其他站点也定义了同名 `map $http_upgrade $connection_upgrade`，完整配置里只能保留一份 `map`。例如其他站点配置已包含该 `map` 时，portfolio 配置里的 `map` 段可以删除。

然后把 `/etc/nginx/sites-available/portfolio` 替换为完整 HTTPS 配置：

```nginx
upstream portfolio_next {
    server 127.0.0.1:40323;
    keepalive 16;
}

server {
    listen 80;
    listen [::]:80;
    server_name my.etedrop.com;

    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    location / {
        return 301 https://my.etedrop.com$request_uri;
    }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name my.etedrop.com;

    ssl_certificate     /etc/letsencrypt/live/my.etedrop.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/my.etedrop.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    client_max_body_size 10M;

    location / {
        proxy_pass http://portfolio_next;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> 注意：如果本机 `http {}` 块中**还没有** `map $http_upgrade $connection_upgrade`，在 `http` 块里加一次（不要加在 `server` 块内）：
> ```nginx
> map $http_upgrade $connection_upgrade {
>     default upgrade;
>     ''      close;
> }
> ```

若 `nginx -t` 报 `/etc/letsencrypt/options-ssl-nginx.conf` 或 `/etc/letsencrypt/ssl-dhparams.pem` 不存在，先补齐 Certbot 的 SSL 参数文件：

```bash
mkdir -p /etc/letsencrypt
cp /usr/lib/python3/dist-packages/certbot_nginx/_internal/tls_configs/options-ssl-nginx.conf \
  /etc/letsencrypt/options-ssl-nginx.conf
cp /usr/lib/python3/dist-packages/certbot/ssl-dhparams.pem \
  /etc/letsencrypt/ssl-dhparams.pem
```

最后重载 Nginx：

```bash
nginx -t
systemctl reload nginx
```

测试自动续期：

```bash
certbot renew --dry-run
```

## 9. 保护后台管理页面

**重要：** 本项目的 `/admin` 页面没有内置登录认证，任何人都可以访问并修改内容。生产环境必须在 Nginx 层加一层 Basic Auth 保护，且**只作用于 `my.etedrop.com` 这个 server 块内**，不影响 `etedrop.com`。

### 9.1 创建密码文件

```bash
apt install -y apache2-utils
htpasswd -c /etc/nginx/.htpasswd_portfolio admin
# 输入并确认密码
```

### 9.2 在 Nginx 配置中添加认证

在 HTTPS 的 `server` 块中，`location /` 之前添加：

```nginx
location /admin {
    auth_basic "Admin Area";
    auth_basic_user_file /etc/nginx/.htpasswd_portfolio;

    proxy_pass http://portfolio_next;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /api/ {
    auth_basic "Admin Area";
    auth_basic_user_file /etc/nginx/.htpasswd_portfolio;

    proxy_pass http://portfolio_next;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

重载 Nginx：

```bash
nginx -t
systemctl reload nginx
```

这样访问 `https://my.etedrop.com/admin` 和 `/api/*` 时需要输入用户名密码，而前台展示页面不受影响。

## 10. 备份

生产数据主要在：

```text
src/data/portfolio.zh.json    # 中文内容
src/data/portfolio.en.json    # 英文内容
public/uploads/               # 上传的图片
.env.local                    # 环境变量（如存在）
```

建议每天备份一次（与 etedrop.com 的备份目录分开）：

```bash
mkdir -p /var/backups/portfolio
tar -czf /var/backups/portfolio/portfolio-$(date +%F).tar.gz \
  /var/www/portfolio/src/data \
  /var/www/portfolio/public/uploads \
  /var/www/portfolio/.env.local
```

建议再把 `/var/backups/portfolio` 同步到对象存储、另一台服务器或本地电脑。定期清理旧备份：

```bash
# 保留最近 30 天的备份
find /var/backups/portfolio -name "portfolio-*.tar.gz" -mtime +30 -delete
```

## 12. 上线检查清单

上线后依次检查：

```text
https://my.etedrop.com          # 前台展示
https://my.etedrop.com/admin    # 后台管理（需输入 Basic Auth 密码）
```

前台检查：

- 页面正常加载，中英文根据浏览器语言自动切换。
- 点击右上角语言切换按钮，页面语言正确切换并刷新。
- 项目作品图片轮播正常，左右箭头和指示点可用。
- 开源项目卡片展示正常，GitHub 链接可跳转。
- 联系方式（邮箱、博客、GitHub）链接正确。
- 页脚版权信息正确。

后台检查：

- Basic Auth 认证生效，未授权无法访问 `/admin`。
- 可以编辑 Hero 区域文案并保存。
- 可以上传头像并保存。
- 可以添加、编辑、删除项目作品，多图上传正常。
- 可以添加、编辑、删除开源项目。
- 切换"内容语言"后，编辑的是对应语言的内容。
- 保存后刷新前台，内容已更新。

i18n 检查：

- 浏览器语言为中文时，首次访问显示中文页面，`<html lang="zh-CN">`。
- 浏览器语言为英文时，首次访问显示英文页面，`<html lang="en">`。
- 切换语言后 cookie 已设置，刷新页面语言保持一致。

## 13. 常见问题

### 502 Bad Gateway

检查应用是否启动：

```bash
pm2 status
pm2 logs portfolio
```

检查 Nginx：

```bash
nginx -t
systemctl status nginx
```

确认端口配置一致：PM2 启动端口、Nginx upstream 端口、`.env.local` 中的 `PORT` 三者必须相同（均为 40323）。

### 子域名和主域名互相影响？

不会。`my.etedrop.com` 和 `etedrop.com` 是 Nginx 中两个独立的 `server` 块，分别监听、分别反代到不同的本机端口，互不干扰。修改其中一个的证书或配置不会影响另一个。

### 前台内容更新后不生效

本项目使用 JSON 文件存储数据，Next.js 在生产模式下会缓存页面。更新内容后如果前台没有变化：

```bash
pm2 restart portfolio
```

如果仍然不生效，清除 `.next` 缓存后重新构建：

```bash
cd /var/www/portfolio
rm -rf .next
npm run build
pm2 restart portfolio
```

### 上传图片失败

检查目录权限：

```bash
mkdir -p /var/www/portfolio/public/uploads
chown -R www-data:www-data /var/www/portfolio/public/uploads
chmod -R 755 /var/www/portfolio/public/uploads
```

如果使用非 root 用户运行 PM2，请把目录 owner 改成运行应用的用户。

检查 Nginx `client_max_body_size` 是否足够（建议 10M）。

### 语言切换不生效

i18n 依赖 cookie 存储语言偏好。检查 Nginx 反向代理是否正确转发了 cookie：

```nginx
proxy_set_header Host $host;
```

如果使用了 CDN（如 Cloudflare），确认缓存规则不会缓存带有 `locale` cookie 的页面响应。建议对 HTML 页面设置 `Cache-Control: no-cache` 或在 CDN 侧配置绕过缓存规则。

### 后台修改内容后前台没有更新

确认保存操作成功（后台显示"已保存"），然后检查 JSON 文件是否已更新：

```bash
cat /var/www/portfolio/src/data/portfolio.zh.json | python3 -m json.tool
```

如果文件已更新但前台未显示，重启应用清除缓存：

```bash
pm2 restart portfolio
```

### 修改 `.env.local` 后没有生效

重新构建并重启：

```bash
npm run build
pm2 restart portfolio
```

### 证书续期失败

`my.etedrop.com` 的证书独立于 `etedrop.com`。若续期失败，先确认 `my` 子域名的 DNS 解析正常、且 ACME 校验路径 `/.well-known/acme-challenge/` 可访问，再执行 `sudo certbot renew --dry-run`。
